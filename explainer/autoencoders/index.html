Squeeze, rebuild, forecast

An autoencoder squeezes data through a narrow bottleneck and rebuilds it on the other side. This page builds the idea up from a 2-D toy that trains live, to handwritten digits, to the variational autoencoder you can sample from. Then it follows the idea into time-series forecasting, through the paper Are Transformers Effective for Time Series Forecasting?. There, a single linear layer turns out to be an autoencoder in disguise.

1

Autoencoders: squeeze, then rebuild

An autoencoder is two networks trained as one. The encoder squeezes an input into a short code; the decoder rebuilds the input from that code. Nobody tells the network what the code should mean. Because the middle is narrow, the only way to rebuild the input well is to keep what varies most across the data and drop the rest.

1.1 Encoder, bottleneck, decoder

input xd numbers→ encoder f→ code zk < d→ decoder g→ rebuilt x̂d numbers
z = f(x), x̂ = g(z), L = mean ‖x − g(f(x))‖²

That one idea has many uses: compression (store z), features for another model, denoising (feed a noisy input, ask for the clean one), and anomaly detection: an input unlike the training data comes back badly rebuilt. In part 5 the same shape becomes a forecaster.

1.2 Live: 2-D points through a one-number bottleneck

Each point has two coordinates; the code has one. Press Train and watch encoder and decoder learn together. The blue curve is everything the decoder can draw, and every reconstruction (orange) has to land on it. A linear autoencoder can only draw a straight line. A nonlinear one (two hidden layers of 24 tanh units on each side) can bend it to follow the data.

A linear autoencoder is PCA. Trained on squared error, a linear AE with k codes spans the same subspace as the top k principal components (Baldi & Hornik, 1989). On the cloud preset its error settles on PCA's, shown next to it. On the arc and wave no straight line can do well, but the nonlinear AE can.

The strip under the plot shows each point's code. When the nonlinear AE has learned the arc, the colors run in order along the strip: it has unrolled the curve, and the code means "how far along the arc". That is the general picture. Data that looks high-dimensional often lies near a lower-dimensional surface; the encoder learns coordinates on that surface, and the decoder learns to draw it.

2

An autoencoder for handwritten digits

Now real data: handwritten digits from MNIST, resized from 28 × 28 to 64 × 64 pixels. The encoder squeezes each image into two numbers, so every image becomes a point in a plane we can look at. Four convolutions halve the image four times (64 → 32 → 16 → 8 → 4 pixels), then two dense layers reduce the 4 × 4 feature map to the code. The decoder mirrors it and turns any point of that plane back into an image. The networks were trained on MNIST's 60,000 training images by build_assets.py and run here; the maps show 2,000 test images. Notebook 01 builds the same models step by step on scikit-learn's smaller 8 × 8 digits.

2.1 Every image becomes two numbers

Each image is drawn as its own digit, at its code. The encoder never saw a label, yet the digits sort themselves into regions, with look-alikes (3, 5, 8, 9) next to each other. Hover a point to compare the image with its reconstruction from just two numbers. Move into empty space and the decoder shows what that point means to it.

2.2 Draw a digit

Draw on the 64 × 64 pad, or start from a real test image and change it. Your drawing is encoded on every stroke. See where it lands and how much of it survives the two-number bottleneck. MNIST's digits were scaled to fit a 20 × 20 box and centered by their center of mass, so the encoder has only seen digits of one size in one place. The page treats your drawing the same way first. Turn that off and draw a small digit in a corner: the encoder no longer recognises it.

2.3 What the decoder draws everywhere

Decode a regular grid of points across the region where the codes live. On data this small the decoder extrapolates gracefully: almost every cell still looks like some digit. The problems are in the layout. The codes have no fixed scale or center, and the digits get very uneven territory. Draw points uniformly in the box and ask which digit owns the nearest code:

So a plain autoencoder gives a good encoder, not a generator. Nothing says which distribution to draw z from, and nothing constrains the decoder where no code ever landed. On richer data (faces, sounds) those regions usually decode to garbage.

3

Variational autoencoder: from points to clouds

Kingma & Welling (2014) turned the autoencoder into a probabilistic model you can sample from: draw a code from a fixed prior, decode it. To make that work, the encoder stops returning a point and returns a small Gaussian cloud, and a second loss term keeps every cloud close to the prior.

3.1 The objective: rebuild well, stay close to the prior

The generative story. First a code, then an image:

z ~ N(0, I), x ~ p(x | z)

Fitting it means maximizing log p(x), an integral over every possible code. The encoder proposes where to look: q(z | x) = N(μ, σ²). For any such q, the log-likelihood is bounded below by the ELBO (evidence lower bound), and its negative is the loss:

L = reconstruction + β · KL

The reconstruction term is the autoencoder's loss. The KL term is the price of each cloud's distance from the prior. It is zero only when μ = 0 and σ = 1, that is, when the code says nothing about the input. Try it for one latent dimension:

3.2 Sampling a code: the reparameterization trick

Backpropagation can't pass through "draw a random sample". The trick is to write the sample as a deterministic function of the encoder's outputs plus outside noise, so that gradients reach μ and σ:

z = μ + σ ⊙ ε

Click an image in the VAE's code space (trained with β = 1). Its cloud is drawn as an ellipse at μ ± 2σ. Draw ε to sample codes inside it: each decodes to a slightly different version of the image.

3.3 A code space you can sample

The KL term packs all codes into the prior's disk, about radius 2.5 against a span of about 30 for the AE. Because neighbouring clouds overlap during training, the decoder has to make sense of the space between them. Switch between the two models, show what the decoder draws everywhere, and generate new digits. The VAE samples z ~ N(0, I); the AE, which has no prior, samples uniformly from its box.

Under the VAE's prior every digit owns close to 10% of the territory. The price is blur: overlapping clouds teach the decoder to average between neighbours. (In notebook 01, a digit classifier is confident about 31% of VAE samples against 58% of the AE's.)

3.4 The β knob

The weight β on the KL term sets the trade-off (Higgins et al., 2017). Small β: sharp reconstructions, codes spread out, back towards a plain AE. Large β: codes squeezed onto the prior, blurry images. Too large: the cheapest solution is to ignore the input. Every cloud collapses onto the prior, KL = 0, and the decoder draws one average digit. This failure is called posterior collapse.

3.5 Walking between two digits

Walk in a straight line between the codes of two images and decode along the way. Both paths cross other digits' territory, because a straight line in a 2-D plane has nowhere else to go. The VAE's frames change more evenly, because its codes are spread out more evenly.

4

What the paper found Zeng, Chen, Zhang & Xu · AAAI 2023

Between 2019 and 2022 a series of Transformers (LogTrans, Informer, Autoformer, Pyraformer, FEDformer) reported big gains in long-term time-series forecasting. Are Transformers Effective for Time Series Forecasting? put them next to a single linear layer, and the linear layer won.

4.1 The task, and an embarrassingly simple baseline LTSF-Linear

Given the last L values of a series, predict the next T (96 to 720 hours on hourly data). LTSF-Linear predicts all T steps at once (direct multi-step, DMS) with one matrix, shared by every variable (channel independence):

past xL = 336→ one matrix WT × L→ future ŷT = 96…720
Linear, NLinear, DLinear

NLinear subtracts the last value and adds it back, which makes it robust to level shifts between training and test data. DLinear splits the window into a trend (25-step moving average) and a remainder, with one matrix for each. The paper's argument for why this can beat attention: self-attention is permutation-invariant, so order only enters through positional embeddings. A single number in a series carries little meaning on its own; the information is mostly in the order.

4.2 Table 2, explorable

The paper's main results on nine benchmarks. Pick a dataset and a horizon. Blue bars are the three LTSF-Linear models, gray bars the five Transformers and the naive Repeat (repeat the last value).

Numbers are copied from the paper's Table 2: multivariate forecasting, errors on standardized data. Transformers use L = 96, their best setting according to the paper; LTSF-Linear uses L = 336. "Improvement" is the paper's IMP. column: best linear model vs best Transformer.

The paper backs this up with diagnostics. Transformers do not get better with a longer look-back window, while linear models do. Turning Informer step by step into a linear model improves it (ETTh1: 0.865 → 0.400). Shuffling the input window barely changes Informer's error but raises Linear's by 81% on average over the horizons: Linear really uses the order. Part 5 runs the same diagnostics on an autoencoder.

4.3 What one linear layer learns

NLinear trained on ETTh1 (hourly load and oil temperature of a power transformer; L = 336 hours, T = 96; test MSE 0.378, paper 0.374). Row h of W holds the weights given to each of the 336 past hours when predicting h hours ahead. Hover to read weights; click a row to plot it.

The diagonal stripes, 24 hours apart, are the paper's Fig. 7 signature: to predict hour t + h, look at the same hour on previous days. That is 32,256 free weights. Part 5 asks how many of them the forecast really needs.

5

An autoencoder that forecasts

Write the linear map as a product W = D E. An encoder E (k × 336) squeezes the past into k numbers; a decoder D (96 × k) expands them into the future. That is an autoencoder whose decoder rebuilds the future instead of the past. It keeps every lesson of the paper: DMS output, one model shared by all variables, NLinear's normalization, and an order-aware linear encoder.

5.1 How many numbers does the past need?

z = E (x − x_L) + b_E, ŷ = D z + b_D + x_L

Each model below was trained end to end on ETTh1 with bottleneck size k (notebook 02). Pick k to see the product DE next to the error curve.

From k = 8 the autoencoder matches NLinear on the test months, with 3,560 parameters instead of 32,352. Cutting NLinear's own W down to rank 8 after training is much worse (MSE 0.41; notebook 02, §4.1). A model trained under the bottleneck puts its few directions where they predict the future. NLinear spends its spare rank on detail that fits the training months but doesn't help on the test months.

5.2 A real forecast, taken apart

With a linear decoder the forecast is literally a sum of k curves, the columns d_j of D, each scaled by one code z_j:

ŷ = x_L + b_D + Σ z_j d_j

Pick a variable and slide through the four test months. The cards below the chart are the pieces z_j d_j, largest first. Hover one to see it in the chart.

5.3 Does it use the order of the past?

The paper's Table 5 test: scramble the input window and see whether the forecast notices. A model that reads temporal order must get worse. In the paper (ETTh1, T = 96), Informer's error barely moved while Linear's more than doubled.

5.4 Train one yourself

Design a synthetic hourly series and train a forecasting autoencoder on it, live (L = 168, T = 48, NLinear normalization, Adam). The reference is the best full linear map (least squares, any rank). A pure daily sine needs only k = 2: every 24-hour sinusoid is a mix of one sine and one cosine. Add the weekly cycle and it needs about 4. Trend and level shifts are handled by the normalization. Watch the decoder curves turn into the series' own rhythms.

6

Forecasts with uncertainty: a conditional VAE

A point forecast says nothing about how sure the model is. The variational half of part 3 adds that. A conditional VAE (Sohn et al., 2015) learns a distribution of futures given the past. Sampling it gives many forecasts, and their spread is the uncertainty.

6.1 The model: a linear AE plus learned deviations

ŷ(z) = linear AE + U z

The prior network reads the past and says how uncertain this window is. During training a posterior network also sees the real future and encodes which deviation actually happened. As in part 3, the loss is reconstruction plus the KL between posterior and prior. To forecast, draw z from the prior, decode, and add the per-hour noise σ_t. Because Uz shifts all 96 hours together, each sample is a coherent alternative future (a warmer day, an earlier dip), not independent noise at each hour.

6.2 Many futures

Bands show the central 50% and 80% of the sampled futures. Thin lines are sampled trajectories without the per-hour noise. Resample to draw new ones.

Measured on all 19,495 test windows (notebook 02, §8), the CVAE's 80% band is a third narrower than the usual "residual error bars", still covers more than 80% of the truth, and has 10% lower CRPS. Its width also changes from window to window, which a fixed residual band cannot do.
