# Autoencoder Explainer

An interactive page about autoencoders and how they apply to time-series forecasting:

1. **Autoencoders.** 2-D points squeezed through a one-number bottleneck, trained live in the browser. A linear AE settles on the PCA line; a nonlinear one bends its curve to follow an arc.
2. **Digits.** An AE with a 2-number code on scikit-learn's 8×8 digits: a latent map with decode-on-hover, a 64×64 drawing pad that is averaged down to the 8×8 input and encoded as you draw, the decoder's map, and how unevenly the digits share the code space.
3. **Variational autoencoders.** The ELBO, an interactive KL term, the reparameterization trick (sample ε and decode), a code space you can sample, the β knob down to posterior collapse, and interpolation.
4. **The paper.** [*Are Transformers Effective for Time Series Forecasting?*](https://arxiv.org/abs/2205.13504) (Zeng et al., AAAI 2023): LTSF-Linear, an explorable copy of Table 2, and NLinear's weight matrix on ETTh1.
5. **An autoencoder that forecasts.** NLinear's map factored as W = D·E. A bottleneck of 8 numbers matches the full matrix. The section takes a real ETTh1 forecast apart into decoder curves, repeats the paper's input-shuffling test, and has a lab where you design a synthetic series and train a forecasting AE live.
6. **Uncertainty.** A conditional VAE on top of the linear AE draws many futures (fan chart, sampled trajectories).

**Live:** https://d2718281828nis.github.io/ML-Transformers/autoencoders/ · in Russian: https://d2718281828nis.github.io/ML-Transformers/autoencoders/ru/

The companion notebooks in [`notebooks/autoencoders/`](../../notebooks/autoencoders/) build every model on this page step by step and report the full experiments.

## How it works

- **Two kinds of models.** The 2-D toy (part 1) and the forecasting lab (part 5.4) train in the browser. `js/nn.js` has a small dense network with backprop and Adam. The lab's full-rank reference is a ridge least-squares solve (Cholesky). The digit models and the ETTh1 models were trained in PyTorch by `tools/build_assets.py` and are only *run* here.
- **Assets.** `assets/digits.json` holds the 1,797 images (one character per pixel). `assets/digit-models.json` holds an AE and four VAEs (β = 0.1, 1, 2, 4). `assets/etth1.json` holds the ETTh1 test period, NLinear, forecasting AEs with k = 1…32, the conditional VAE and their test-set scores. Weights are base64 float32. Total ≈ 1.2 MB.
- **Two languages.** `index.html` (English) and `ru/index.html` (Russian) hold the prose. Strings generated by the scripts come from `js/i18n.js`, which picks the language from `<html lang>`.
- **No build step, no framework.** `js/app.js` boots the page. `js/toy.js`, `js/digits.js`, `js/paper.js` and `js/forecast.js` render the sections. `js/charts.js` and `js/util.js` hold the drawing helpers. Formulas use KaTeX from a CDN. The CSS repeats the design tokens of the GPT-2 explainer (`../css/style.css`) instead of importing them, so the two pages can change independently.

## Run locally

```bash
cd explainer
python3 -m http.server 8000   # then open http://localhost:8000/autoencoders/
```

## Rebuild the models

```bash
python explainer/autoencoders/tools/build_assets.py   # torch, numpy, pandas, scikit-learn; ~2 min on a CPU, downloads ETTh1 once
```

The training recipes are the ones in the notebooks: the same architectures, seeds and splits, and the official LTSF-Linear training schedule for ETTh1.

## Verify

```bash
node explainer/autoencoders/tools/check.mjs   # Node >= 22
```

This runs the page's JavaScript in Node and checks three things. Digit encoders and decoders, NLinear, the forecasting AE and the CVAE's prior mean are compared with the PyTorch outputs saved in `assets/checks.json`. The browser trainer's backprop is compared with finite differences. Everything agrees to within 1e-5.
